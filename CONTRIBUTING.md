# Contributing to fugusense

Thank you for your interest in contributing! This project focuses on Apple device research, jailbreak tools, tweaks, and related open-source work. We welcome contributions of all kinds code, documentation, testing, bug reports, and ideas.

Please read this document carefully before submitting issues or pull requests.

## Code of Conduct

Be respectful, constructive, and inclusive. Harassment, personal attacks, spam, or off-topic discussions will not be tolerated.  

We reserve the right to close issues/PRs or ban users who violate these standards.

## Important Legal & Safety Notes

- Jailbreaking carries risks. It can void warranties, brick devices, introduce security vulnerabilities, or cause data loss. Contributors and users assume all responsibility.
- This project is for **educational and research purposes**. Do not use it to distribute pirated software, bypass paid services illegally, or violate Apple’s terms of service in ways that break local laws.
- In many jurisdictions (including the US under certain DMCA exemptions), jailbreaking a device you own for personal use is legal. Distributing copyrighted material or certain tools may not be. Know your local laws.
- Never submit code that enables unauthorized access to other people’s devices or accounts.
- Do not post or request paid/closed-source jailbreak tools, exploits that are still under embargo, or anything that could harm users.

By contributing, you agree that your contributions are provided under the same license as the project (see `LICENSE`).

## Ways to Contribute

### 1. Report Bugs
- Search existing issues first.
- Use the bug report template (if available).
- Include:
  - Device model + iOS/macOS/visionOS version
  - Jailbreak tool + version (if applicable)
  - Exact steps to reproduce
  - Expected vs actual behavior
  - Relevant logs / crash reports (redact personal info)
  - Screenshots or screen recordings when helpful

### 2. Suggest Features / Improvements
- Open a feature request issue.
- Clearly describe the problem and your proposed solution.
- Explain why it would benefit the project.

### 3. Improve Documentation
- Fix typos, clarify instructions, add missing steps, or improve the README.
- Documentation PRs are highly appreciated.

### 4. Submit Code
We accept pull requests for:
- Bug fixes
- New features (discuss larger changes in an issue first)
- Performance improvements
- Refactoring / code quality
- Test coverage
